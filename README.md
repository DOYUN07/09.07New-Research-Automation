# 지원사업 공고 브리핑

34개 공공기관 게시판을 매일 아침 훑어서, 키워드에 맞는 **신규 공고만** 골라 메일로 보냅니다.

- 매일 **08:00 (한국시간)** 자동 발송
- **마감된 공고는 제외**
- **게시일 기준 최근 10일** 이내 공고만
- **한 번 보낸 공고는 다시 안 보냄**
- 마감일을 읽을 수 없는 공고는 `마감일 확인필요`로 표시해서 포함
- 포함 키워드 / 제외 키워드 / 수신자 / 기관 목록 전부 파일에서 수정

## 설치 (한 번만)

### 1단계. 저장소 만들기

GitHub에서 새 저장소를 만들고(Private 권장), 이 폴더의 파일을 전부 올립니다.

```bash
git init
git add .
git commit -m "init: 공고 브리핑"
git branch -M main
git remote add origin https://github.com/<계정>/<저장소>.git
git push -u origin main
```

> 웹으로 올려도 됩니다: 저장소 → Add file → Upload files → 폴더째 드래그.
> 단, `.github` 폴더는 웹 업로드에서 숨겨질 수 있으니 확인하세요.

### 2단계. Gmail 앱 비밀번호 만들기

일반 Gmail 비밀번호로는 안 됩니다. **앱 비밀번호**가 따로 필요합니다.

1. https://myaccount.google.com/security 접속
2. **2단계 인증**을 켭니다 (이미 켜져 있으면 넘어감)
3. https://myaccount.google.com/apppasswords 접속
4. 이름을 아무거나(예: `공고브리핑`) 넣고 생성
5. 나오는 **16자리 문자열**을 복사 (공백은 빼도 되고 넣어도 됩니다)

### 3단계. GitHub Secrets 등록

저장소 → **Settings** → **Secrets and variables** → **Actions** → **New repository secret**

| 이름 | 값 | 필수 |
|---|---|---|
| `SMTP_USER` | 보내는 Gmail 주소 (예: `qjagh6414@gmail.com`) | **필수** |
| `SMTP_PASSWORD` | 2단계에서 만든 앱 비밀번호 16자리 | **필수** |
| `MAIL_TO` | 받는 사람들 (쉼표 구분). 비워두면 `config.yaml`의 목록을 씁니다 | 선택 |
| `DATA_GO_KR_KEY` | 공공데이터포털 인증키 | 선택, 나중에 |

> **Secrets를 등록하기 전에도 프로그램은 정상적으로 돌아갑니다.**
> 메일만 안 보내고, 결과를 Actions의 Artifacts에 파일로 남깁니다.
> 나중에 Secrets를 추가하면 그 다음 실행부터 자동으로 발송이 시작됩니다.

### 4단계. Actions 켜기

저장소 → **Actions** 탭 → `I understand my workflows, go ahead and enable them` 클릭

### 5단계. 먼저 진단 한 번 돌리기 ⭐

**이걸 꼭 먼저 하세요.** 34개 기관 중 어디가 되고 어디가 막히는지 알려줍니다.

**Actions** → 왼쪽에서 **기관 수집 진단** → **Run workflow** → 초록 버튼

2~3분 뒤 실행 화면 아래에 표가 나옵니다:

| 기관 | 상태 | 수집 | 최신 게시일 | 비고 |
|---|---|---|---|---|
| 부산정보산업진흥원 | ✅ | 15건 | 2026-09-07 | 마감일 파싱 15/15 |
| 전북테크노파크 | ❌ | — | — | 연결 시간 초과 |

- ✅ 정상
- ⚠️ 접속은 되는데 목록을 못 읽음 → 선택자 지정 필요
- ❌ 접속 실패 → 차단이거나 URL이 바뀐 것

**이 표를 저에게 보내주시면 실패한 기관을 고쳐서 다시 드리겠습니다.**

### 6단계. 시험 발송

**Actions** → **매일 공고 브리핑** → **Run workflow** → `dry_run` 체크 해제 → 실행

메일이 오면 끝입니다. 이후로는 매일 아침 8시에 자동으로 옵니다.

## 매일 쓰면서 고치는 법

### 받는 사람 추가

`config.yaml` 을 GitHub 웹에서 열고 (연필 아이콘) 한 줄 추가한 뒤 Commit.

```yaml
recipients:
  - qjagh6414@gmail.com
  - 동료이름@zeroweb.co.kr      # ← 이렇게 추가
```

### 키워드 바꾸기

같은 파일의 `include_keywords`(포함) / `exclude_keywords`(제외)를 고칩니다.
**제외 키워드가 포함 키워드보다 우선**입니다. 제목에 제외 키워드가 하나라도 있으면 무조건 버립니다.

공고가 너무 많이 오면 → 포함 키워드를 줄이거나 제외 키워드를 늘리세요.
공고가 너무 안 오면 → `require_keyword: false` 로 바꾸면 키워드와 무관하게 전부 옵니다.

### 기관 추가 / 빼기

`institutions.yaml` 에서 `enabled: false` 로 바꾸면 그 기관은 건너뜁니다.

새 기관을 추가할 때는 세 줄이면 됩니다:

```yaml
  - id: 아무거나_영문
    name: 기관 이름
    url: "공고 목록 페이지 주소"
```

선택자는 안 적어도 됩니다. 범용 파서가 목록을 자동으로 찾습니다.
자동 인식이 안 되면 진단에서 ⚠️로 나오고, 그때 선택자를 추가하면 됩니다.

### 발송 시각 바꾸기

`.github/workflows/daily-brief.yml` 의 cron을 고칩니다. **UTC 기준**이라 한국시간에서 9를 빼야 합니다.

| 원하는 한국시간 | cron |
|---|---|
| 07:00 | `0 22 * * *` |
| 08:00 | `0 23 * * *` ← 현재 |
| 09:00 | `0 0 * * *` |
| 평일만 08:00 | `0 23 * * 0-4` |

> GitHub Actions의 예약 실행은 서버가 붐빌 때 5~20분 늦어질 수 있습니다. 정시 보장은 안 됩니다.

## 파서가 목록을 찾는 방법

기관마다 HTML이 다 달라서 선택자를 34개 다 지정하면 관리가 안 됩니다. 그래서:

1. 페이지의 모든 `<tr>` / `<li>` 중 **더 이상 중첩되지 않고 링크를 가진 것**을 후보 행으로 봅니다
2. 같은 부모를 가진 행들을 **한 그룹**으로 묶습니다
3. **날짜를 가진 행이 많은 그룹**에 높은 점수를 줍니다 (게시판 목록엔 날짜가 있고, 메뉴엔 없습니다)
4. 최고점 그룹을 공고 목록으로 채택합니다

날짜 해석도 자동입니다:
- `2026-09-07 ~ 2026-09-30` 처럼 붙어 있는 두 날짜 → 접수기간으로 보고 뒤쪽을 마감일로
- 기간 밖에 날짜가 하나 더 있으면 → 그게 게시일
- `26.09.05` 같은 2자리 연도도 처리

자동 인식이 안 되는 기관만 `institutions.yaml` 에 `row_selector` 등을 적어주면 됩니다.

## 2차 진단 결과 (v1.1) → v1.2에서 수정

33곳 중 **27곳 정상**. 전북테크노파크·저출산고령사회위원회가 살아났고, 제목·게시일 수정도 확인됐습니다.

| 증상 | 어디서 | 원인 | 수정 |
|---|---|---|---|
| 멀쩡하던 곳이 **0건으로 회귀** | NIPA | 첨부파일 판별을 `class` 이름으로도 했는데, 본문 링크에 `down`/`file` 이 든 class가 붙어 있어 제목이 통째로 걸러짐 | class 기준 판별 삭제. 그리고 **모두 걸러지면 필터 없이 다시 고르는 안전장치** 추가 |
| 게시일이 **2026-12-31** | 전북테크노파크 | 목록에 게시일이 없고 `마감 2026-12-31 18:00` 만 있는데 그걸 게시일로 씀 | 날짜 앞의 `마감`·`종료` 표시를 읽어 마감일로만 쓰고 게시일에서는 제외 |
| 제목이 여전히 두 번 | 부산테크노파크 | 두 span 내용이 완전히 같지 않아(한쪽은 말줄임, 한쪽은 `재공고` 라벨) 기존 비교가 안 걸림 | 한쪽이 다른 쪽의 앞부분이면 긴 쪽만 채택 |
| HTTP 404 반복 | 한국사회적기업진흥원 | 게시판 주소가 바뀐 것으로 보임 | 비활성화. 정확한 주소를 알면 `url`만 고쳐 다시 켜면 됨 |

**회귀 방지 장치도 넣었습니다.** 문서 정리(`nav`/`header` 제거) 후 결과가 0건이면 **원본으로 다시 파싱**합니다. 게시판을 `<header>` 안에 넣어둔 사이트가 있어서, 정리가 오히려 목록을 지우는 사고를 막습니다.

**아직 목록 인식이 안 되는 곳** — 부산시민운동지원센터.
진단에 `--dump`가 들어 있어, 다시 돌리면 실패한 기관의 원본 HTML이 **Artifacts의 `out/html/`** 에 저장됩니다. 로그가 아니라 **Artifacts**를 받아야 이 파일이 들어 있습니다.

## 3차 진단 결과 (v1.2) → v1.3에서 보완

v1.2 수정은 전부 확인됐습니다: NIPA 10건 복구, 전북TP 마감일 20/20 + 게시일 미인식(정상), 한국사회적기업진흥원 8건.

**다만 정부 부처 6곳이 한꺼번에 접속 실패했습니다** — 산업통상부·중소벤처기업부·보건복지부·농림축산식품부·저출산고령사회위원회·KOTRA. 전부 `Max retries exceeded`(연결 자체가 안 됨)이고, **바로 전 실행에서는 모두 정상이었습니다.**

코드 문제가 아니라 **정부 사이트 방화벽이 그 시점의 GitHub 서버 IP를 막은 것**입니다. 이 기관들은 같은 정부통합전산센터 뒤에 있어서 한꺼번에 막힙니다.

그래서 v1.3에 **재시도 라운드**를 넣었습니다:

1. 33개 기관을 한 바퀴 돈다
2. 접속 실패한 곳만 골라낸다 (타임아웃·연결 실패·403·429·5xx)
3. **45초 쉰 뒤 새 연결로 한 번 더** 시도한다
4. 그래도 안 되면 메일 하단 '수집 실패'에 표시된다

일시적 차단은 대개 이걸로 넘어갑니다. 기관당 대기 시간도 25초 → 30초로 늘렸습니다.

> 어느 날 특정 기관이 실패했다고 해서 설정이 잘못된 게 아닙니다. 며칠 연속 같은 곳이 실패할 때만 주소를 의심하세요.

## 4차 진단 결과 (v1.3) → v1.4에서 수정 · **32/33 정상**

재시도 라운드가 작동해 정부 부처 6곳이 전부 복구됐습니다(25 → 30곳). 남은 두 곳은 원본 HTML을 받아 원인을 정확히 잡았습니다.

| 증상 | 어디서 | 원인 | 수정 |
|---|---|---|---|
| 목록 인식 0건 | 중소벤처기업부 | 행(`tr`) 안에 첨부파일 목록이 `<ul><li>`로 들어 있는데, '행 안에 tr이나 li가 있으면 상위 행'으로 판단해 **모든 행을 건너뜀** | **같은 태그**가 안에 있을 때만 상위 행으로 판단 (tr은 tr만, li는 li만) |
| 제목 뒤에 메타데이터 | 중소벤처기업부 | 모바일용 `<a>`가 제목 + 담당부서 + 공고번호를 통째로 감쌈 | 짧은 쪽이 긴 쪽의 앞부분이면 짧은 쪽 채택. `담당부서`·`공고번호` 등 라벨부터는 잘라냄 |
| 목록 인식 0건 | 부산시민운동지원센터 | 행마다 감싸는 div가 따로 있어(`div.table_td > div.table_td_line`) **형제가 아님** → 부모별로 묶으면 전부 1개짜리 그룹 | 부모별 묶기에 더해 **태그+class가 같은 것끼리도** 묶어보고 점수 높은 쪽 채택 |

**KIAT만 남았습니다.** 원본 HTML을 확인한 결과 목록이 JavaScript로 그려져 정적 수집이 불가능합니다. `enabled: false` 상태이므로 실제 운영에는 영향이 없습니다.

**마감일이 안 잡히는 것은 대부분 정상입니다.** 게시판 목록에 등록일만 있고 마감일 컬럼이 없는 사이트가 많습니다(복지부·농식품부·산업통상부 등). 이런 공고는 `마감일 확인필요`로 표시되어 그대로 옵니다.

## 문제가 생겼을 때

**메일이 안 와요**
Actions → 최근 실행 → 로그를 봅니다. `SMTP 미설정` 이면 Secrets를 등록하세요.
`Username and Password not accepted` 면 앱 비밀번호가 아니라 일반 비밀번호를 넣은 것입니다.

**같은 공고가 또 왔어요**
사이트가 상세 URL을 매번 다르게 주는 경우입니다. 해당 기관에 `detail_url`을 지정해야 합니다.

**공고가 하나도 안 와요**
`--dry-run` 으로 실행해 로그의 `수집 N → 채택 M` 줄을 보세요.
`키워드없음`이 크면 포함 키워드가 좁은 것이고, `제외키워드`가 크면 제외 목록이 넓은 것입니다.

**한 기관만 계속 실패해요**
`institutions.yaml` 에서 `enabled: false` 로 꺼두면 나머지는 정상 동작합니다.
